# 인라인 각주 출처 (hover 미리보기)

- 작성일: 2026-09-03
- 상태: 설계 검토 대기
- 관련 코드: `rag_service.py`, `responses.py`, `Message.tsx`, `SourceCitation.tsx`, `api.types.ts`
- 선행 작업: [크로스인코더 리랭킹](2026-09-03-reranking-design.md)

## 1. 문제

지금 출처는 답변 **아래** 접기식 목록에 모여 있다. 사용자가 어떤 문장의 근거를
확인하려면 목록을 펼치고, 5개 청크를 읽어 가며 **어느 것이 그 문장을 뒷받침하는지
스스로 추측해야 한다.** 답변과 근거가 화면에서 분리돼 있다.

`QA_PROMPT` 규칙 2번은 이미 모델에게 인용을 요구한다.

```
2. **출처 인용**: 답변에 사용한 정보의 출처를 [출처: 문서명] 형식으로 표시하세요.
```

[크로스인코더 리랭킹 작업](2026-09-03-reranking-design.md)에서 컨텍스트에
`[출처: 문서명, p.N]` 헤더를 실어, 모델이 지어내지 않고 인용할 수 있게 만들었다.
그래서 답변 본문에는 이미 `[출처: …]` 문자열이 들어 있다 — 다만 **그냥 텍스트로
렌더링될 뿐**이라 클릭할 수도, 내용을 미리 볼 수도 없다.

이 작업은 그 표시를 각주로 바꾸고, 마우스를 올리면 해당 청크를 보여준다.

### 1.1 문서명으로는 청크를 특정할 수 없다

`[출처: 문서명]`을 그대로 각주로 쓰지 않는 이유다. 리랭킹 이후 상위 5개 청크는
**대부분 같은 PDF에서 온다.** 문서명만으로는 5개 중 어느 것인지 가릴 수 없고,
모델이 이름을 줄여 쓰거나(`성남시 기본계획`) 다르게 적으면 연결이 끊긴다.

번호 인용(`[1]`)은 배열 인덱스와 1:1로 떨어져 이 문제가 없다. GPT·Perplexity가
쓰는 방식이기도 하다.

## 2. 설계 원칙

- **번호는 문서를 따라다녀야 한다.** 위치로 계산하지 않는다(§3.1이 그 이유다).
- **없는 근거를 링크처럼 보이게 하지 않는다.** 모델이 존재하지 않는 번호를 쓰면
  각주로 만들지 않고 원문 그대로 둔다.
- **하단 목록을 대체하지 않는다.** 각주는 훑는 용도, 목록은 전체를 읽는 용도다.
  도표 원본처럼 카드에 담기 어려운 것은 목록이 계속 책임진다.
- **백엔드는 번호만 책임진다.** 각주를 그리는 일은 전적으로 프론트엔드 몫이다.

## 3. 설계

### 3.1 번호는 재배치 전에 부여한다 — 이 설계의 핵심

같은 `docs` 리스트가 두 갈래로 갈라지는데 **순서가 서로 다르다.**

```
retriever.ainvoke()  →  LongContextReorder가 U자로 재배치한 순서
   │
   ├─ rag_service.py:326  context = _format_context(docs)   ← 재배치된 순서 그대로
   └─ rag_service.py:348  _format_sources(docs)  → rerank_score 내림차순으로 되돌림
```

컨텍스트를 앞에서부터 훑어 `[1] [2] [3]`을 매기면 그것은 **재배치된 순서**의
번호다. 반면 사용자가 받는 `sources[0]`은 **점수 1위**다. 모델이 `[1]`이라고 쓰면
엉뚱한 청크가 열린다. 테스트 없이는 눈치채기 어려운 종류의 어긋남이다.

그래서 번호를 **재배치 전에** 메타데이터에 심는다. 기존 불변식 — 「점수는 반드시
재배치 전에 심는다」 — 과 같은 이유이고 같은 자리에 붙는다.

```
similarity_search → similarity_score 부착 → 리랭킹 → citation_index 부착
                                                          │
                                                    LongContextReorder
                                                          │
                              ┌───────────────────────────┴──────────────┐
                     _format_context (헤더에 번호)          _format_sources (같은 번호를 응답으로)
```

`citation_index`는 리랭킹으로 상위 `retrieval_k`개를 확정한 **직후**, 즉
`_format_sources`가 쓰게 될 점수 내림차순 그대로 1부터 매긴다. 리랭킹이 꺼져
있으면 벡터 점수 순서가 그 자리를 대신한다.

### 3.2 컨텍스트 헤더

```
[1] 2035 성남시 노후계획도시정비기본계획.pdf p.12
노후계획도시 공간적 범위(분당신도시)는 총 1,996만㎡이며…

[2] 2035 성남시 노후계획도시정비기본계획.pdf p.3
본 계획의 목표연도는 2035년으로 하며…
```

번호와 문서명을 **둘 다** 단다. 번호는 인용을 위한 것이고, 문서명과 쪽은 모델이
지금 어느 문서를 읽고 있는지 판단하는 데 쓰인다. 리랭킹 작업에서 문서명 헤더를
넣은 이유가 그대로 유효하므로 빼지 않는다.

`QA_PROMPT` 규칙 2번은 번호 인용을 요구하도록 바꾼다.

### 3.3 응답

`SourceDocument`에 `citation_index: Optional[int] = None`을 추가한다. 프론트엔드는
답변 본문에서 찾은 번호로 이 배열을 조회한다. **배열 위치가 아니라 이 필드로
찾는다** — 정렬이 바뀌어도 안전하다.

`Optional`인 이유는 `_format_sources`가 리트리버를 거치지 않은 문서를 받을 수
있기 때문이다(테스트가 직접 호출하는 경로가 그렇다). 그때는 `None`이 되고,
프론트엔드는 그런 출처를 각주 대상에서 제외한다 — `similarity_score`가 없을 때
`-inf`로 밀어내는 기존 방어와 같은 성격이다.

### 3.4 프론트엔드 — 각주 렌더링

답변은 `ReactMarkdown`이 그리므로 `[1]`은 그냥 텍스트로 나온다. 마크다운이 만든
**텍스트 노드에서 `[숫자]` 패턴을 찾아** 각주 컴포넌트로 치환한다
(`ReactMarkdown`의 `components` prop으로 `p`·`li` 등의 자식 텍스트를 가공).

- **유효한 번호** → 위첨자 각주 `¹` + hover 카드
- **없는 번호** (모델이 `[7]`이라 썼는데 출처가 5개) → 치환하지 않고 원문 `[7]`을
  그대로 둔다

코드 블록 안의 텍스트는 치환하지 않는다.

### 3.5 hover 카드 내용

| 항목 | 출처 |
|---|---|
| 문서명 | `document_name` |
| 쪽 · 청크 번호 | `page`, `chunk_index` |
| 원문 발췌 (3줄에서 잘림) | `content` |
| 도표 썸네일 | `image_urls[0]` — **있을 때만** |
| Relevance · Rerank | `similarity_score`, `rerank_score` |

`image_urls`는 그 페이지에서 도표가 인식됐을 때만 채워지므로 카드 높이가 출처마다
달라진다. 의도한 동작이다.

### 3.6 마우스가 없는 환경

hover는 터치에서 동작하지 않는다. **탭하면 열리고 다시 탭하면 닫히게** 한다.
데스크톱에서는 hover 그대로다.

## 4. 범위

**포함**

- `citation_index` 부여(재배치 전) 및 `SourceDocument` 필드 추가
- `_format_context`의 헤더 형식 변경
- `QA_PROMPT` 규칙 2번을 번호 인용으로 변경
- 프론트엔드 각주 렌더러와 hover 카드
- 단위 테스트 (§7)

**제외**

- **하단 출처 목록 변경.** 그대로 둔다. 각주와 역할이 다르다.
- **각주 클릭 시 하단 목록으로 스크롤.** 나중에 원하면 별도로 붙인다.
- **모델이 인용하지 않을 때의 강제.** 프롬프트로 요구할 뿐, 안 하면 각주가 없다.
- **각주 번호를 답변 등장 순서로 다시 매기기.** 번호는 출처 목록 순서와 같게
  유지한다. 본문 등장 순서로 다시 매기면 목록과 어긋난다.
- **재인덱싱.** 검색·인덱싱 단계는 건드리지 않는다.

## 5. 설정

**추가·제거되는 설정이 없다.** 인라인 각주는 항상 켜져 있다. 모델이 번호를
쓰지 않으면 각주가 생기지 않을 뿐이고, 그때도 하단 목록은 그대로 동작한다.

## 6. 한계

- **모델 협조에 달렸다.** 번호 인용을 안 하면 각주가 하나도 생기지 않는다.
  프롬프트 변경이 실제로 인용을 끌어내는지는 §7.3에서 확인한다.
- **답변 텍스트가 바뀐다.** 프롬프트를 고치므로 기존 답변의 인용 스타일과
  달라진다. 온도가 0이어도 컨텍스트 헤더가 바뀌므로 답변 자체가 달라질 수 있다.
- **`[숫자]`가 본문에 우연히 나올 수 있다.** 모델이 인용이 아닌 의도로
  `[1]`을 쓰면 각주로 오인된다. 유효 범위 안의 번호라면 구분할 방법이 없다.
- **마크다운 각주 문법과 다르다.** `[^1]` 같은 표준 각주가 아니라 자체 패턴이므로,
  나중에 마크다운 각주를 지원하게 되면 충돌을 검토해야 한다.
- **발췌는 3줄에서 잘린다.** 전체는 하단 목록에서 봐야 한다.

## 7. 검증

### 7.1 백엔드 단위 테스트

| 테스트 | 지키는 것 |
|---|---|
| 번호는 점수 순서 | 재배치가 켜져 있어도 `citation_index`가 `_format_sources` 순서(1,2,3…)와 일치하는지 |
| 재배치 후 보존 | `LongContextReorder`를 거친 뒤에도 각 문서가 자기 번호를 유지하는지 |
| 컨텍스트 헤더 | `[1] 문서명 p.N` 형식으로 조립되는지, 번호가 메타데이터 값과 같은지 |
| 페이지 없는 문서 | TXT/DOCX에서 `p.None`이 나오지 않는지 |
| 응답 전달 | `SourceDocument.citation_index`가 메타데이터 값과 같은지 |
| 번호 없는 문서 | 메타데이터에 번호가 없으면 `citation_index`가 `None`이 되고 터지지 않는지 |

**핵심은 첫 두 개다.** §3.1의 어긋남을 막는 것이 이 작업의 가장 중요한 계약이다.
재배치를 켠 상태에서 컨텍스트의 번호와 출처 목록의 번호가 같은 청크를 가리키는지
문자열 수준에서 단언한다.

### 7.2 프론트엔드

| 테스트 | 지키는 것 |
|---|---|
| 유효 번호 치환 | `[1]`이 각주 요소가 되는지 |
| 없는 번호 보존 | 출처가 5개일 때 `[7]`이 원문 텍스트로 남는지 |
| 번호로 조회 | 배열 위치가 아니라 `citation_index`로 찾는지 (일부러 섞어서 검증) |
| 도표 없는 청크 | `image_urls`가 비면 썸네일 자리가 사라지는지 |

### 7.3 수동 확인

- 실제 질문을 던져 **모델이 실제로 번호 인용을 쓰는지** 확인한다. 쓰지 않으면
  프롬프트 문구를 조정한다.
- 각주에 마우스를 올려 카드가 본문을 가리지 않는지, 화면 가장자리에서 잘리지
  않는지 본다.
- 인용이 하나도 없는 답변에서 기존과 똑같이 보이는지 확인한다.
